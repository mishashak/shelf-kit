# 꽂이 (shelf) 사용 안내

문서를 선반에 꽂아 두고, **누가 볼지는 문서마다** 정하는 팀 문서 라이브러리입니다.
파일을 주고받는 대신 주소 하나를 넘기는 것이 요점입니다.

이 저장소는 꽂이를 **쓰는 사람**을 위한 것입니다. 서버 코드는 들어 있지 않고, 꽂이 주소와 계정은
쓰는 조직마다 다르므로 여기 적지 않습니다. 관리자에게 주소를 받아 시작하세요.

## 왜 파일 대신 링크인가

| 파일로 넘기면 | 꽂이로 넘기면 |
|---|---|
| 판이 갈립니다. 누가 어느 판을 보는지 모릅니다 | 주소가 하나라 항상 최신을 가리킵니다 |
| 새 판이 나오면 다시 보내야 합니다 | 파일만 교체하면 링크는 그대로입니다 |
| 한 번 나간 파일은 회수가 안 됩니다 | 열람 범위를 나중에도 좁힐 수 있습니다 |
| 누가 봤는지 모릅니다 | 조회 기록이 남습니다 |

## 사람이 쓰는 법

### 1. 들어가기

1. 꽂이 주소로 들어가 이메일과 비밀번호로 로그인합니다. 계정이 없으면 로그인 화면의 **가입 신청**을 누릅니다(관리자 승인 후 열립니다).
2. 나눠준 비밀번호로 처음 들어오면 **비밀번호 변경 화면에서 막힙니다.** 바꾸기 전에는 다른 화면으로 가지 못합니다. 고장이 아니고, 미루지 못하게 해 둔 것입니다.

### 2. 화면 셋

| 화면 | 하는 일 |
|---|---|
| **홈 (전체 문서)** | 모든 선반의 문서를 한자리에. 검색은 제목, 조직, 태그, 참석자를 함께 훑습니다 |
| **선반** | 한 선반만 봅니다 |
| **찾기** | 검색은 제목, 조직, 태그, **참석자**를 함께 훑습니다. 필터는 선반, 태그, 조직, 언어 넷이고 정렬은 등록일순과 제목순입니다 |
| **문서 화면** (`/d/<슬러그>`) | 문서를 읽습니다. 우측 상단 ☰ 에 문서 정보 수정, 열람 범위, 게스트 공유, 내려받기가 모여 있습니다 |

### 3. 어느 선반에 꽂나

| 선반 | 넣는 것 |
|---|---|
| 덱꽂이 | **안에서 밖으로.** 외부 피칭, 소개, 홍보 |
| 보고꽂이 | **안에서 안으로.** 내부 기획, 공유, 전달, 교육 |
| 내부회의꽂이 | 사내 회의록 |
| 외부회의꽂이 | 파트너, 외부 업체 미팅 |
| 잡꽂이 | 어디에도 안 맞는 것 |

가르는 기준은 **형식이 아니라 힘의 방향**입니다. 슬라이드로 만들었어도 사내에서 넘기며 발표한 기획이면
보고꽂이입니다. 청중이 퍼블리셔, 투자자, 파트너, 플랫폼이면 덱꽂이입니다. 선반은 분류일 뿐이고
열람 권한과는 무관합니다.

### 4. 올리기

우측 상단 **문서 올리기**.

**파일** (`.html` / `.zip` / `.md` / `.pdf`)

HTML이나 덱을 직접 만드는 중이면 [화면물 만들기](docs/HTML-DOCS.md)를 먼저 보십시오.
로컬에서는 멀쩡한데 꽂이에서만 깨지는 자리가 셋 있습니다.

- `.html`: 이미지와 CSS가 전부 파일 안에 들어 있어야 합니다. 밖의 파일을 참조하면 서버가 거부합니다.
- `.zip`: 이미지나 영상이 따로 있으면 이쪽입니다. **압축 루트에 `index.html`이 오도록** 묶습니다(폴더를 묶는 게 아니라 폴더 안 내용물을 묶습니다).
  - ⚠️ **zip 안에서도 이미지를 본문에 base64로 박으면 이득이 없습니다.** 이미지를 파일로 두는 것이 zip의 목적입니다. 크기 규약은 [화면물 만들기](docs/HTML-DOCS.md) 1-B절에 있습니다.
- `.md`: 회의록, 메모. 서버가 읽기용 화면으로 구워 줍니다.
- `.pdf`: 원본을 그대로 보관하고 뷰어를 씌워 보여줍니다. 내려받으면 원본이 그대로 나옵니다.

**채우는 칸**

| 칸 | 무엇을 적나 |
|---|---|
| 제목 | 필수 |
| 선반 | 필수 |
| URL 슬러그 | 주소에 쓰입니다. 영문 소문자와 숫자, 하이픈을 권합니다. 비우면 제목에서 자동 생성되는데, 한글 제목이면 한글 주소가 나와 외부 도구에서 깨집니다 |
| 한 줄 요약 | 목록에서 제목 아래 붙습니다. **내용 요약이 아니라 계기와 대상**을 적습니다("무엇을 위해 누구에게") |
| 조직 | 작성 부서 |
| 분류(태그) | 검색용. 아래 [태그](#9-태그) 참고 |
| 누가 볼 수 있나 | 다음 절. 가장 중요한 칸입니다 |
| 버전 | 기본 `v0.1.0` |

**선반마다 요구하는 칸이 다릅니다.** 회의꽂이는 날짜와 참석자를 챕니다. 보고꽂이는 같은 자리를
"수신처"로 부릅니다. 화면이 그때그때 알려주니 라벨을 그대로 따르면 됩니다.

파일명, 버전 올리는 기준, 제목과 요약 쓰는 법은 [문서 규약](docs/CONVENTIONS.md)에 있습니다.

### 5. 열람 범위 (가장 중요한 칸)

| 고르는 것 | 누가 보나 |
|---|---|
| **고른 분께 열기** (기본값) | 체크한 사람만. 나머지 사내 구성원에게는 **목록에서도 안 보입니다** |
| **사내 구성원 전체** | 소속이 있는 사내 전체. 여기에 더해 고른 사람은 소속과 무관하게 열립니다(협력사 공유는 이쪽) |

**기본은 좁은 쪽입니다.** 아무도 안 고르고 올리면 올린 사람과 관리자만 봅니다. 그래서 "올렸는데 안 보인대요"의
답은 거의 항상 이 칸입니다. 팀이 봐야 하는 문서면 볼 사람을 고르거나 사내 전체로 넓히세요.
지금 안 정해도 문서 화면에서 언제든 바꿉니다.

누가 이 칸을 바꿀 수 있나. 가르는 선은 등급이 아니라 **내가 올린 문서인가**입니다.

| | 바꿀 수 있는 범위 |
|---|---|
| 올린 본인 | **자기가 올린 문서는 등급과 무관하게** 정할 수 있습니다 |
| 관리자 | 전부 |
| 편집자 | 자기가 볼 수 있는 문서 |
| 그 밖 | 남이 올린 문서는 못 바꿉니다 |

남의 문서까지 열 수 있으면 주소만 알고 자기를 열람자로 얹을 수 있어서 통제가 통제가 아니게 됩니다.
반대로 자기 문서까지 막아 두면 올린 사람이 팀에 열어 주려고 매번 관리자를 불러야 합니다. 그 사이를 가르는
선이 "내가 올린 것인가"입니다. 남의 문서를 열어야 하면 올린 사람이나 관리자에게 요청하세요.

관리자는 설정과 무관하게 모든 문서를 열람합니다.

⚠️ **열람 범위보다 먼저 걸리는 것이 소속입니다.** 계정이 승인됐어도 **소속이 비어 있으면 사내 전체
공개 문서조차 보이지 않습니다.** 목록이 텅 비어 보이면 열람 범위가 아니라 소속을 먼저 확인하세요.
관리자에게 요청하면 됩니다. 자세한 것은 [접근권한과 관리](docs/SHELF-ADMIN.md)에 있습니다.

### 6. 계정 없는 상대에게 보여주기

문서 화면 ☰ → **게스트 공유** → **비밀번호 발급**. 나온 링크와 비밀번호를 주면 계정 없이 그 문서 하나만 열립니다.

- **발급하지 않은 문서는 링크를 알아도 비밀번호 칸조차 뜨지 않습니다.** 필요할 때만 발급하는 것이 기본입니다.
- 비밀번호는 나중에 다시 확인할 수 있습니다. 상대가 "그거 비번 뭐였죠" 하고 물어도 됩니다.
- **초기화하면 이미 열어 두고 보던 사람도 그 자리에서 끊깁니다.** 회수 수단이 이것입니다.
- 열리는 건 그 문서 한 벌뿐입니다. 목록, 검색, 다른 문서는 게스트에게 닫혀 있습니다.

### 7. 문서 화면에서 되는 것

우측 상단 ☰ 에 모여 있습니다.

| 기능 | 설명 |
|---|---|
| 내보내기 | **PDF와 HTML**로 받습니다. PDF로 올린 문서는 원본을 그대로 줍니다 |
| 웹 편집 | 텍스트와 위치를 화면에서 고칩니다. 파일을 교체하면 초기화됩니다. **본문이 6MB를 넘는 문서에서는 빠집니다** |
| 문서 정보 수정 | 제목, 요약, 조직, 태그, 일자, 참석자 |
| 열람 범위 | 위 5절 |
| 게스트 공유 | 위 6절 |

문서 안에 체크박스를 두면 **누가 언제 체크했는지가 서버에 남고 이력이 보존됩니다.** 여러 사람이 같은
문서를 보며 진행 상황을 공유할 수 있습니다.

### 8. 같은 문서의 새 판

**새로 올리지 마세요.** 문서 화면에서 **파일 교체**를 씁니다.

| | 파일 교체 | 새로 올리기 |
|---|---|---|
| 주소 | 그대로 | 새 주소가 생깁니다 |
| 열람자 설정 | 그대로 | 처음부터 다시 |
| 조회 기록, 요약 | 이어집니다 | 옛 문서에 남습니다 |
| 링크를 받았던 사람 | 최신을 봅니다 | **옛 판을 계속 봅니다** |

버전은 서버가 올립니다. 웹 편집으로 손봤던 텍스트와 위치는 교체하면 초기화됩니다.

### 9. 태그

검색용이고 권한과는 무관합니다. **있는 태그를 먼저 고르세요.** 비슷한 태그를 새로 만들면 검색이 갈려서
나중에 아무도 못 찾습니다. 유형 1~2개에 제품이나 프로젝트 1개가 관행입니다.

### 10. 언어판

같은 내용의 다른 언어는 새 문서로 올리지 않고 **한 문서 아래 언어판**으로 답니다(목록 화면의 수정에서 추가).

- 버전은 언어판마다 따로 올라갑니다. 영문만 고쳤는데 국문 번호가 올라가면 번호가 사실을 못 나타내기 때문입니다.
- 목록의 표지 그림은 **대표 언어 것만** 굽습니다. 카드 표지는 하나뿐이라 나머지 언어판의 표지는 쓰이는 자리가 없습니다.
- 예전에 언어별로 따로 올려 밖으로 나간 링크는 그대로 그 언어로 열립니다.
- 언어판이 둘 이상이고 언어가 정해지지 않았을 때만 **고르는 화면**이 뜹니다. 주소에 언어를 지정해 들어오면 바로 열립니다.
- **파일 교체는 그 언어판만** 새 버전으로 만듭니다. 다른 언어를 추가하거나 삭제하는 것은 목록 화면의 수정에서 합니다.
- **열람 범위는 문서 한 벌에 붙습니다.** 국문판만 좁게 열 수는 없습니다.

### 11. 이어지는 문서는 부모를 지정합니다

회의록 아래에 그 회의에서 나온 결과 문서를 붙일 수 있습니다. 한 단만 씁니다.

이유는 게스트 열쇠입니다. 열쇠는 문서마다 하나라서, 회의록을 밖에 보내 놓고 결과 문서를 새 주소로
올리면 같은 자리에서 이어지는 이야기인데도 상대가 링크와 비밀번호를 또 받아야 합니다. **부모를
지정하면 자식이 부모의 열쇠로 열립니다.**

## 막히면

| 증상 | 원인과 조치 |
|---|---|
| 목록이 아예 텅 비어 있음 | **소속이 비어 있습니다.** 관리자에게 소속 지정을 요청하세요 |
| 목록에 그 문서가 안 보임 | 열람 범위입니다. 올린 사람이나 관리자에게 열람자 지정을 요청하세요 |
| "올릴 수 있는 선반이 없습니다" | 계정이 아직 승인 대기이거나 잠긴 상태입니다. 관리자에게 확인하세요 |
| HTML을 올렸는데 이미지가 깨짐 | 밖의 파일을 참조하는 HTML입니다. 폴더를 zip으로 묶어 올리세요(루트에 `index.html`) |
| 비밀번호 변경 화면에서 못 나감 | 정상입니다. 바꾸면 열립니다 |
| 같은 문서가 두 벌 생김 | 새로 올린 것입니다. 옛 문서를 지우고 앞으로는 파일 교체를 쓰세요 |

## Claude Code로 올리기

설치는 3단계, 5분입니다. → **[skills/shelf-upload/README.md](skills/shelf-upload/README.md)**

스킬을 넣어 두면 이렇게 말하는 것으로 끝납니다.

> 이 폴더 발표자료 덱꽂이에 올려줘. 제목은 "OO 소개덱"으로.

선반과 태그 목록을 스킬에 적어 두지 않고 올릴 때마다 서버에서 받아오도록 해 두었습니다.
선반이나 태그가 늘어도 스킬을 다시 나눠줄 필요가 없습니다.

### 갱신은 손으로 한 번 당겨 옵니다

스킬은 각자 홈 폴더로 **복사된 사본**입니다. 여기 저장소를 고쳐도 이미 복사해 간 사람의 것은
그대로이니, 고쳐진 것을 받으려면 한 번 당겨 와야 합니다. 그래서 설치는 클론으로 하십시오.

```bash
cd ~/shelf-kit && git pull && cp -R skills/shelf-upload ~/.claude/skills/
```

Windows와 자세한 절차는 [설치 가이드 4절](skills/shelf-upload/README.md#4-갱신--고쳐진-것을-받아오기)에 있습니다.

반대로 **갱신하지 않아도 늘 최신인 것** 셋이 있습니다. 선반과 태그 목록(서버에서 받아옵니다),
이 저장소의 사용법과 규약 문서(링크로 읽으면 그 자리가 최신입니다), 계정 권한과 토큰(서버가 판정합니다).
