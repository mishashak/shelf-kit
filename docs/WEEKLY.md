# 주간보고 브라우저

주차별로 쌓이는 정기 보고를 **한 문서에 모아, 좌측에서 회차를 골라 보는 단일 HTML**로 만드는
규약입니다.

상위 규칙은 [WEB-REPORT](WEB-REPORT.md)를 상속하고, 충돌하면 정기 보고 특성 때문에 이 문서가
우선합니다. 공통 기술 규약은 [HTML-DOCS](HTML-DOCS.md)에 있습니다.

## 1. 언제 쓰나

- 주간이나 격주, 월간처럼 **같은 양식이 반복 생성**되고 과거 회차를 나란히 보고 싶을 때입니다.
- 회차마다 PDF를 따로 열어보면 추세가 안 보이고 파일이 흩어집니다. 이 포맷은 회차 목록과 회차 상세,
  추세 그래프를 한 화면에 둡니다.
- 단발 보고서라면 쓰지 않습니다. **회차가 3개 이상 쌓일 때부터** 값어치가 있습니다.

## 2. 파이프라인

```
회차별 원본 HTML(자동 생성물) → 파서 → weeks.json → 단일 HTML(브라우저)
```

- **원본을 정본으로 둡니다.** 브라우저는 원본을 읽어 다시 그리는 뷰어이지 별도 사본이 아닙니다.
  내용을 고칠 일이 생기면 브라우저 코드가 아니라 **원본 회차 파일**을 고치고 다시 빌드합니다.
  그래야 다음 빌드에서 되돌아가지 않습니다.
- 회차 파일명은 `<접두사>_<YYMMDD>.html`로 통일합니다. 빌드가 이 패턴을 훑어 자동으로 회차를 잡습니다.
- 견본과 구버전 파일(`sample_*`)은 제외합니다. 더미 데이터가 섞여 통계를 오염시킵니다.
- 중간 산출물(`weeks.json`)을 남깁니다. 파싱이 깨졌는지 눈으로 확인하는 가장 빠른 방법입니다.

## 3. 문서 골격

### 좌측 고정 패널

- 상단에 작은 라벨, 문서 제목, 부제(조직 표기)를 둡니다.
- 회차 버튼을 **최신순**으로 나열합니다. 각 버튼은 상태 점과 기간, 요약 수치(완료 N / 마감 N /
  초과 N)입니다.
- **패널에 제작 경위나 운영 설명을 쓰지 않습니다.** "매주 자동 생성됩니다", "원본은 어디에
  게시됩니다" 같은 문장은 독자에게 쓸모가 없고 사족으로 읽힙니다. 실제로 지적받아 삭제한 문구입니다.
- 모바일에서는 가로 스크롤 탭으로 접습니다.

### 최상단 3분할 헤더

좌에서 우로 세 열이고 열 사이는 세로 구분선으로 나눕니다.

| 열 | 내용 |
|---|---|
| 1열 | **미니 달력**(해당 월, 보고 주차 행을 키컬러 띠로 강조)과 그 아래 기간 `MM/DD(요일)~MM/DD(요일)` |
| 2열 | **상태 배지** 한 행과 지표 박스 3개(지난주 완료 / 기한 초과 / 이번주 마감 예정) |
| 3열 | **최근 N주 업무 현황** 제목과 완료 건수 막대그래프(최대 16주) |

- **날짜는 문서 안에서 한 번만 글자로 씁니다.** 예전 판은 좌측 목록, 제목, 보고기간 줄, 작성일,
  막대 라벨까지 같은 날짜가 다섯 번 나왔습니다. 시각(달력)이 한 번, 글자가 한 번이면 충분합니다.
  작성일은 문서 맨 아래 출처 줄로 내립니다.
- 미니 달력은 **주차 시작일이 속한 달**을 그립니다. 달을 걸친 주는 시작 달 그리드의 마지막 행에 다음
  달 날짜가 함께 들어오므로 그대로 표시됩니다.
- 지표 박스는 **내용 높이만** 씁니다. 열 높이에 맞춰 늘리면 세로로 허옇게 비어 보입니다.
- 막대그래프는 값 라벨을 막대 위에 얹고 **막대 아래에 날짜를 적지 않습니다.** 날짜 반복의 주범입니다.
  지금 보는 회차만 키컬러로 칠합니다.
- 회차가 16주를 넘으면 최근 16주만 그립니다. 제목의 숫자는 실제 표시 개수로 자동 표기합니다.

### 본문 섹션 순서

1. **주의 및 결정 사항** (판단이 필요한 것. 가장 위)
2. **마일스톤** (단계가 있는 프로젝트만. 없으면 섹션을 통째로 생략)
3. **일감 외 진행 사항** (있을 때만)
4. **이번주 마감 예정**
5. **진행 중**
6. **지난주 완료** (근거 성격이라 맨 아래, 접힘)
7. 출처 줄 (상태 기준 정의와 생성일)

순서 원칙은 **지금 결정할 것 → 맥락 → 앞으로 할 일 → 이미 한 일**입니다. 완료 목록이 위에 오면
"읽을거리"가 먼저 나와 판단이 묻힙니다.

## 4. 개념블록

### 판정 배지 넘버 카드 (주의 및 결정 사항)

```
[01] [리스크]
1차 테스트 결과, UI와 조작이 최약점
전체 평균 3.04점으로 기준 3.5에 미달했습니다.
```

- 카드 머리에 **번호와 판정 배지**를 답니다. 배지 어휘는 넷으로 고정합니다.
  `리스크` / `주의` / `양호` / `참고`.
- **배지에 글자를 넣습니다.** 색만으로 심각도를 표현하면 색약 사용자와 흑백 인쇄에서 정보가
  사라집니다.
- 2열 그리드(최소 폭 330px)로 둡니다. 세로 길이가 절반으로 줄고 스캔이 빨라집니다.
- 카드 좌측 색 바 같은 장식은 쓰지 않습니다. 배지가 이미 판정을 말합니다.

### 진행 궤적 (마일스톤)

- 표 대신 **가로 스테퍼**를 씁니다. 완료 구간은 채운 점과 진한 연결선, 현재 단계는 키컬러 점에 링,
  남은 단계는 빈 점입니다.
- 각 단계 아래에 단계명과 목표 시점, 있으면 D-day 배지를 답니다.
- 스테퍼 아래에 **직전 완료와 다음 단계** 카드 두 장만 비고를 펼칩니다.
- 나머지 단계 비고는 **접어서** 표로 둡니다. 판단은 펼치고 근거는 접습니다.
- 단계가 없는 회차는 이 섹션을 아예 만들지 않습니다. **빈 표를 남기지 않습니다.**

### 날짜 묶음 목록 (마감 예정)

- 항목을 **마감일로 묶고** 날짜 헤더를 답니다. 헤더에 건수, 오늘이면 오늘 배지, 기한 초과가 섞이면
  초과 배지를 답니다.
- 항목 문구와 담당자, 분류 태그는 원본 그대로 둡니다. 형식만 바꿉니다.
- 그룹 헤더에 오늘 배지가 있으면 **항목별 오늘 표시는 뺍니다.** 같은 정보를 두 번 보여주지 않습니다.

### 접기

- 초기 상태는 전부 접힘입니다. 라벨은 내용 예고형으로 씁니다(`개발 10건 목록`,
  `단계별 비고 전체 6단계`). `더 보기`는 열 이유를 못 만듭니다.
- 접힌 것은 안 읽힌다고 가정합니다. **접혀도 논지가 성립해야 합니다.**
- 결론, 경고, 액션, 미결은 절대 접지 않습니다.
- 표식은 `[+]`와 `[−]`입니다. 셰브론(`>`)은 링크로 오인됩니다. 마이너스는 하이픈이 아니라
  U+2212를 써야 `+`와 획 길이가 맞습니다.
- **인쇄할 때 자동으로 전부 펼칩니다.** `beforeprint`에서 열고 `afterprint`에서 되돌립니다.
  안 넣으면 PDF에서 근거가 통째로 빠집니다.

## 5. 텍스트 규칙

### 말투

- **모든 완결 문장은 합니다체입니다.** 표 셀, 배지 설명, 툴팁, 접힌 안쪽까지 예외가 없습니다.
  내부 문서라도 마찬가지입니다.
- 라벨과 항목은 개조식 명사 종결을 허용합니다(`기한 초과 3건`, `일정 미정`).
- 명령조와 독촉조를 쓰지 않습니다. 요청은 "확인 부탁드립니다" 수준으로 씁니다.

### 한 건의 형식

```
<b>라벨</b><br>본문
```

- **라벨**은 무슨 건인지 한눈에 잡히는 명사구로 20자 내외입니다. 대상에 상태나 날짜를 붙입니다.
  `1차 테스트 D+6 지연`, `기한 초과 3건`, `7/31 마감 4건, 담당자 부하 집중` 같은 식입니다.
- **본문**은 짧은 문장 1~2개, 합쳐서 90자 이내입니다.
- **한 문장에 여러 절을 이어 붙이지 않습니다.** 실제로 고친 사례입니다.
  - 전(116자 한 문장): "1차 테스트(7/21~24)는 현재 D+6 지연 상태로, 이번 주 완료 예정인 전투
    시스템 리팩토링/전투 씬 UI 개선/데이터 세이브 등 핵심 태스크들이 1차 완성도를 좌우하므로 이번 주
    마감 준수 여부를 함께 점검하면 좋겠습니다."
  - 후: 라벨 `1차 테스트 D+6 지연` + 본문 "전투 시스템 리팩토링, 전투 씬 UI 개선, 데이터 세이브가
    이번 주 마감입니다. 이 태스크들이 1차 완성도를 좌우합니다."
- 라벨을 본문에서 되풀이하지 않습니다.
- 격려나 인사말을 넣지 않습니다. "이번 주도 함께 힘내봐요" 류는 삭제합니다.

### 무엇을 쓰나 (사건이지 변화가 아닙니다)

본문에 쓰는 것은 넷입니다. **그 회차에 무슨 일이 있었나, 무엇이 끝났나, 무엇이 진행 중인가,
무엇이 막혀 있나.**

- **"지난 회차 대비 무엇이 달라졌나"를 쓰지 않습니다.** 작성자가 지난번에 본 상태와 이번에 본
  상태의 차이는 **작성자의 사정**이지 독자의 정보가 아닙니다. 독자는 일이 어디까지 갔는지를 보러
  옵니다.
  - 쓰지 않는 문장입니다. "지난 회차에서 마감이 지났던 6건이 완료로 바뀌었습니다", "날짜가 없던
    29건이 자리를 잡았습니다", "지난 회차 20건과 이번 50건은 모집단이 다릅니다".
  - 이렇게 씁니다. "이번 주에 A와 B, C를 끝냈습니다", "일정이 잡혔습니다. 9월까지 X, 10월에
    Y입니다".
  - 고치는 법은 하나입니다. **주어를 보고서에서 일감으로 돌립니다.** "완료로 바뀌었습니다"의
    주어는 시트 칸이고, "끝냈습니다"의 주어는 사람입니다.
- **문서 자기언급을 쓰지 않습니다.** "이번 보고부터", "다음 회차 보고에 함께 잡힙니다", "지난
  보고에서는" 같은 말입니다. 좌측 패널의 제작 경위 금지와 같은 뿌리입니다.
- 회차 간 증감은 **헤더 지표 박스와 추세 그래프가 맡습니다.** 그것이 그 자리에 있는 이유이고,
  본문에서 같은 말을 문장으로 되풀이하면 자리만 차지합니다.
- 예외는 하나입니다. 증감 자체가 **판단거리**면 주의 및 결정 사항 카드로 올립니다. 기한 초과가 몇
  회차째 늘어 원인을 봐야 하는 경우입니다. 그때도 서술은 "무엇이 왜 밀렸나"이지 "지난번과
  다르다"가 아닙니다.

### 기호와 표기

- **엠대시(—)와 가운뎃점(·)을 쓰지 않습니다.** 쉼표, 슬래시, 괄호, 콜론, 문장 분리로 대신합니다.
  값이 없는 칸은 하이픈(`-`)입니다.
- 로마숫자 소제목과 제목 앞 장식 막대를 쓰지 않습니다. 위계는 크기와 굵기로만 줍니다.
- 숫자는 `tabular-nums`로 정렬해 자릿수가 흔들리지 않게 합니다.
- 한국어는 `word-break: keep-all`입니다.

### 색 이름을 문구에 박지 않습니다

"파란 막대가 지금 보는 주차입니다" 같은 캡션은 키컬러가 다른 인스턴스에서 거짓말이 됩니다.
"진한 막대"처럼 색에 의존하지 않는 표현을 씁니다.

## 6. 색 규칙

- **키컬러는 인스턴스당 하나이고, 용도는 "지금 보는 회차"를 표시하는 것 전용입니다.** 선택된 회차
  버튼, 달력의 해당 주, 선택된 막대, 오늘 배지, 현재 마일스톤 점입니다.
- **판정색은 따로 셋입니다.** 리스크는 적, 주의는 주황, 양호는 녹입니다. 회색은 참고입니다.
  판정색은 배지와 상태 점에만 쓰고 블록 전체를 칠하지 않습니다.
- 키컬러와 판정색이 겹치면(주황 키컬러에 주황 주의 배지) 키컬러는 위치 표시로만, 판정색은 배지
  안쪽으로 한정해 역할을 분리합니다.
- **카테고리에 색을 칠하지 않습니다.** 분류마다 색을 주는 방식은 강조를 죽입니다.
- 바탕은 흰색이고 위계는 여백과 헤어라인으로 줍니다. **다크 테마를 쓰지 않습니다.** 본문 대비가
  낮아 읽기 어렵다는 지적으로 라이트로 전환한 이력이 있습니다.

## 7. 데이터 규칙

- **일감 목록(시트)이 정본입니다.** 완료와 마감, 진행 목록의 문구와 담당자, 날짜를 임의로 바꾸지
  않습니다.
- **시트가 모든 것을 담지 못합니다.** 채널이나 회의에서만 오간 사실(테스트 실시, 결과 보고서,
  문서 공유, 의사결정)은 시트에 없습니다. 이런 것은 `일감 외 진행 사항` 블록에 수기로 채웁니다.
  - 각 항목에 **날짜와 출처**를 붙입니다. "결과 보고서 v0.3.0(7/27)" 같은 식입니다.
  - 수치를 인용하면 어느 문서 몇 버전 기준인지 병기합니다.
- **상충은 숨기지 않습니다.** 시트 상태와 실제가 다르면 정정하고, 무엇을 왜 고쳤는지 보고합니다.
  원인이 자동화 입력값이면 **그 입력값(config, 시트)도 같이 고칩니다.** 표시만 고치면 다음 회차에
  그대로 재발합니다.
- 추정과 사실을 섞지 않습니다. 미확인은 미확인이라고 적습니다.

## 8. 인스턴스 만드는 법

한 벌의 빌드 스크립트를 공유하고 인스턴스별 config로 분기합니다. **스크립트를 복제하지 않습니다.**

- **config에 들어가는 것**: 문서 제목, 부제, 회차 파일 접두사, 데이터 소스 ID, 마일스톤(단계가
  있으면), 분류 이모지.
- **빌드 인자**: 어떤 config를 읽을지, 어디에 쓸지, 키컬러를 무엇으로 할지.
- 제목에 이미 "보고"가 들어 있으면 뒤에 "주간보고"를 덧붙이지 않습니다.
- 키컬러는 **실제 디자인 시스템의 값**을 가져다 씁니다. 임의로 만든 색은 촌스러워집니다. 본문
  텍스트에 쓸 때는 흰 배경 대비 4.5:1을 넘도록 명도만 낮춘 파생값을 별도로 둡니다.

## 9. 뷰어 함정

플랫폼이 원본 HTML을 그대로 서빙하지 않고 가공해 iframe에 넣습니다. 자세한 것은
[HTML-DOCS 3절](HTML-DOCS.md)에 있고, 주간보고에서 특히 걸리는 것만 여기 적습니다.

⚠️ 자동 화면맞춤을 피하려고 거는 `transform: perspective(1000px)`은 **본문에만** 겁니다.
최상위 컨테이너에 걸면 `position: sticky` 사이드바의 기준이 래퍼로 바뀌어 스크롤할 때 같이
흘러갑니다. 회차 목록이 고정 사이드바인 이 포맷에서는 반드시 걸립니다.

## 10. 검수 체크리스트

**텍스트**
- [ ] 말투가 합니다체인가 (표 셀, 배지, 접힘 안쪽까지)
- [ ] 한 건이 라벨과 90자 이내 본문 형식인가 (긴 복문이 남아 있지 않은가)
- [ ] 라벨을 본문에서 되풀이하지 않았는가
- [ ] 격려와 인사말, 제작 경위 문구가 없는가
- [ ] "지난 회차 대비" 서술과 문서 자기언급이 0건인가 (본문 주어가 보고서가 아니라 일감인가)
- [ ] 엠대시와 가운뎃점이 0건인가 (**빌드 산출물을 문자 단위로 세어** 확인)

**중복**
- [ ] 같은 날짜가 화면에 두 번 이상 글자로 나오지 않는가
- [ ] 그룹 헤더와 항목에 같은 배지가 겹치지 않는가
- [ ] 제목에 "보고"가 두 번 들어가지 않았는가

**색**
- [ ] 키컬러가 위치 표시에만 쓰였는가
- [ ] 판정색이 판정에만 쓰였는가 (카테고리 색칠 없음)
- [ ] 판정 배지에 글자가 있는가 (색만으로 구분하지 않는가)
- [ ] 색 이름을 문구에 박지 않았는가

**레이아웃**
- [ ] 지표 박스가 열 높이에 맞춰 늘어나지 않았는가
- [ ] 폭 390 / 900 / 1400에서 `scrollWidth == clientWidth`인가
- [ ] 좁은 폭에서 3열이 세로로 쌓이고 스테퍼가 격자로 접히는가
- [ ] 회차를 최대치(16주)로 채웠을 때 막대와 값 라벨이 겹치지 않는가
- [ ] 사이드바가 스크롤 후에도 `top == 0`인가 (**계산값으로** 확인)

**데이터**
- [ ] 일감 목록 원문을 임의로 바꾸지 않았는가
- [ ] 일감 외 진행 사항에 날짜와 출처가 붙어 있는가
- [ ] 시트와 실제가 어긋난 것을 정정하고 **입력값까지** 고쳤는가
- [ ] 단계가 없는 회차에서 마일스톤 섹션을 생략했는가 (빈 표 없음)

**배포**
- [ ] 접힌 블록이 인쇄에서 펼쳐지는가
- [ ] `<base href>`를 주입한 사본에서 앵커와 배율이 정상인가
- [ ] **서빙된 라이브 응답으로** 최종 확인했는가

## 11. 하지 말 것

실제로 지적받아 고친 것들입니다.

1. **다크 테마.** 본문 대비가 낮아 읽기 어렵습니다.
2. **날짜 반복.** 목록과 제목, 보고기간 줄, 작성일, 막대 라벨에 같은 날짜를 넣습니다.
3. **한 문장에 절을 계속 잇는 서술.** 100자 넘는 한 문장은 스캔이 안 됩니다.
4. **박스를 열 높이에 맞춰 늘리기.** 가운데가 세로로 비어 보입니다.
5. **표로 늘어놓은 마일스톤.** 단계 진행 상황이 한눈에 안 들어옵니다.
6. **제목 중복.** "주간 업무 보고 주간보고"입니다.
7. **제작 경위 문구.** "자동 생성된 보고를 한자리에 모은 것입니다"입니다.
8. **자동화 입력값을 안 고치고 표시만 정정.** 다음 회차에 같은 오류가 다시 찍힙니다.
9. **지난 회차 대비 서술.** "지난주엔 없던 29건이 자리를 잡았습니다"는 작성자의 관찰기이지
   독자의 정보가 아닙니다. 증감은 지표와 그래프가 말하고, 본문은 항목 이름으로 말합니다.
